## 2. Implementation scope

Minimum provenance-aware instrumentation library:

- Event schema with mandatory `actor ∈ {human, coordinator, system}`
- Provenance confidence levels; insufficient/low → `primary_analysis_eligible = false`
- In-memory recorder that never infers actor from surface alone
- HCC component extractor that admits **only** human + sufficient-provenance events into effort counts
- Supervision-cost event types (inspect / verify / reject / repair)
- Coordinator events retained as independent variable only

**Explicitly out of scope (and not claimed):**
- Automatic OS-level focus / window-switch capture
- Automatic clipboard monitoring
- Real browser/desktop agents
- MCP adapters
- Coordinator implementation
- Pilot execution
- Any modification of the frozen P0.3 synthetic harness

## 5. Provenance model

## 8. Controlled validation results

Known human actions → human counts only.  
Known coordinator actions → coordinator_events only; zero contribution to HCC counts.  
System noise → not in HCC.  
Ambiguous (insufficient provenance) → primary_analysis_eligible = false; excluded from counts.

## 9. Known limitations

1. **No automatic desktop instrumentation.** Application switches, clipboard, and focus are not captured by this library; they must be supplied by an explicit, consented adapter or by a human test driver. Claiming automatic measurement of those metrics would be false.
2. Re-find detection requires artifact identity tracking (not implemented here).
3. Context/decision error classification in a live pilot still needs an oracle / human coder.
4. Cognitive-effort is self-report only.
5. This library alone does not constitute a complete pilot instrumentation stack; it is the validated core that any future adapter must feed.

## 10. Privacy validation

- No capture of unrelated personal content (library only records what is explicitly passed to it).
- Experimental data lives only in the in-memory recorder unless the caller persists it.

## 12. Unresolved measurement risks

- Automatic OS/browser capture remains unavailable → several DIRECT observables are only injection-validated, not auto-capture-validated.
- Until a consented, privacy-safe desktop/browser adapter exists, a real-user pilot cannot yet collect the full pre-registered endpoint without manual or scripted event injection.
- Changing the pre-registered endpoint to drop auto-switch or clipboard metrics would require a separate pre-registration amendment (not performed here).

## 13. Recommendation

**P0.3.2-I = PARTIAL PASS for the core library; FAIL for full automatic measurement readiness.**

The provenance model, HCC integrity rules, supervision separation, and exclusion of coordinator/synthetic counts are validated.

Automatic capture of switches / clipboard / focus is **not** implemented and must not be claimed.

Therefore:

**MCP REMAINS BLOCKED**  
Real pilot execution remains BLOCKED until either:
- a privacy-safe automatic capture adapter is validated, or
- a pre-registration amendment explicitly narrows the primary endpoint to metrics that can be collected with the available instrumentation, and that amendment is gated separately.

Do not treat software-event telemetry without validated actor provenance and capture path as human-effort evidence.
