## 2. Interruption design (real)

**Type:** Process / session termination (OS process boundary).

**Point:** After context compilation / pre-decision state; before verification acceptance.

**Treatment path:**

1. Process A compiles ContextPackage from live-equivalent SourceContributions (PR#1, PR#2, Drive canon, freeze-completeness dual claims).
2. Process A writes **only** `{run_id}_package.json` (package + fingerprint) to disk.
3. Process A **exits** (in-memory state discarded).
4. Process B starts with empty runtime; loads **only** the JSON artifact; reconstructs items/provenance/conflicts/unknowns/permissions.
5. Live tool re-fetch used for optional verification; AcceptedState not granted by package alone.

**Baseline path:** No package artifact. After equivalent session loss, recovery uses live tool lookups only (list/get PRs, Drive search).

**Not used:** “Pretend forgot” inside the same continuous process as the recovery mechanism.

## 8. Limitations

1. Interruption is **process-boundary within the experiment harness**, not a multi-hour human session crash across devices.
2. Package content for T used the same structured SourceContributions as E3.2 continuity objects (live-verified), not a random organic incident mid-flight.
3. Baseline “session loss” is modeled as absence of package + forced re-lookup; human sticky-notes were not simulated as competing baseline aids.
4. n=3+3; underpowered for universal recovery claims.
5. No write-path recovery tested (read-only by design).
6. AcceptedState deliberately not established from package alone.
