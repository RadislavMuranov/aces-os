## 1. Experimental question

Can the ACES Context Compiler preserve enough context, provenance, uncertainty and state information to safely reconstruct and resume a cross-system workflow after an **actual** interruption?

## 3. Interruption mechanism (real)

**Type:** Process / session termination with loss of in-memory runtime context.

**Injection point:** After T1 context compilation (or B equivalent pre-decision state), **before** final verification/acceptance.

**Mechanism:**

1. Pre-interruption process writes the only allowed persisted artifact(s).
2. Process exits (OS process boundary).
3. Recovery process starts with **empty runtime memory** relative to the prior process.
4. Recovery may use only: (a) persisted artifact(s), (b) live re-fetch from external systems for verification.

**Treatment persisted artifact:** Serialized `ContextPackage` JSON (`to_dict`) + material fingerprint.  
**Baseline persisted artifact:** None (ordinary user has at most ephemeral notes; this experiment models session loss without ACES package).

**Forbidden:** “Pretend the agent forgot” while the same process retains full in-memory context as the recovery path.

---

## 4. Recovery mechanism

**Baseline:** Re-discover state via live tool lookups only; rebuild decision context manually.

**Treatment:** Load persisted ContextPackage JSON in a **new process**; restore items, provenance, unknowns, conflicts, permissions; optionally re-fetch sources to verify; must not invent OBSERVED from UNKNOWN or resolve CONFLICT silently.
