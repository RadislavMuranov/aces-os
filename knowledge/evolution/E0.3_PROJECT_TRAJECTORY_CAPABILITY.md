## 1. Observed failure (current engineering experience)

Agent can correctly execute:

`FAIL → BLOCKED → STOP`

and still **lose project trajectory**: it does not reliably determine the **next admissible step** (authorized transition, dependencies, evidence location, recovery path).

This is treated as an **observed operational failure**, not as permission to invent a Memory Layer.

---

## 2. Research hypothesis (not adopted)

> The project may need continuous Project State / Project Memory preserving CURRENT STATE, INTENT, CONSTRAINTS, DEPENDENCIES, DECISIONS, EVIDENCE, AUTHORIZED TRANSITIONS, NEXT VALID ACTION, and RECOVERY.

**Critical distinction under test:**

> The gap may not be absence of a Project Memory *layer*, but absence of a **single binding mechanism** that already-existing State + Intent + Constraints + Dependencies + Decisions + Evidence + Next Action + Recovery into one continuous **execution trajectory**.

## 6. Synthesis under ECP-001 (no new architecture)

### 6.1 Is a new Project Memory *layer* justified?

**Not yet.**

| ECP-001 test | Result |
|--------------|--------|
| Observed failure? | **YES** — trajectory loss after FAIL→BLOCKED→STOP |
| Existing mechanisms insufficient? | **Not proven as architectural absence** — State, Decision, Evidence, Checklist, Authz, Reality Layer, STOP all exist as principles/specs |
| Gap only integration/execution? | **Plausible primary explanation** |
| Minimal change to existing architecture enough? | **Likely candidate** — bind existing records into explicit NEXT VALID ACTION on STOP |

### 6.2 Preferred interpretation

**IDENTIFY MINIMAL GAP (process/binding), not new Memory Layer.**

Actual gap (candidate, not implemented):

> After a terminal STOP/BLOCKED outcome, there is no **mandatory, single, evidence-backed emission of NEXT VALID ACTION** (branch, gate, or explicit WAIT) bound to CURRENT STATE + CONSTRAINTS + DECISIONS + EVIDENCE.

Components already partially present:
- STOP as valid result (ECP-001 / practice)
- Master Check / gates
- Branch Protocol (how to open next step)
- Provenance / ledger practice in this session
- Reality Layer NOW/IMPORTANT/NEXT (Master Protocol)
- ASA Decision / Evidence / Memory *kinds* (schema only)

What is missing in observed failure mode:
- **Forced binding** of those pieces into one recoverable trajectory tip at STOP time.

### 6.3 Duplication risk

Creating “Project Memory Layer” would risk duplicating:
- ASA MemoryObject / DecisionObject / EvidenceObject
- Corpus UPI provenance
- Master Protocol Reality Layer
- Evolution Branch Protocol + ledger
- Claimed SCE Runtime governed transitions

→ High duplication risk if treated as new architecture.

### 6.4 Minimal intervention candidate (documentation only — not built)

**CANDIDATE GAP (process):**  
On every BLOCKED/STOP, require an explicit structured tip:

`CURRENT_STATE | CONSTRAINTS | EVIDENCE_REFS | DECISION | NEXT_VALID_ACTION | OR WAIT`

Implemented later only if E0.4+ confirms this is not already covered by SCE Runtime / existing gates — **out of scope for E0.3**.

**NO NEW ARCHITECTURE** in this step.
